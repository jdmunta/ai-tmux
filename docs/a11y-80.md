# Accessibility Audit v2: WO-C2E5A3 "AI tmux" (`ait`)

## Scope and assumptions
- The delivered UI is still a keyboard-only terminal dashboard (`src/render.js`, `src/ui.js`, `src/keys.js`, `src/dashboard.js`). The HTTP API, the CLI and the new port-fallback code (`src/port.js`, `src/serve.js`, `bin/serve.js`) have no visual UI.
- WCAG 2.2 AA is written for web content. I apply it by analogy to a TUI:
  - "Semantics and landmarks" becomes screen structure and reading order.
  - "Focus" becomes the selection and dialog input focus.
  - Colour contrast depends on the user's terminal palette.
  - The README is checked as a document.
- This is a static review. I ran nothing and used no screen reader.
- **Change request v2:**
  - CR1 (port fallback) touches no screen layout. Its only user-facing output is two plain-text lines on stderr and stdout.
  - CR2 (README) is a documentation change.
  - The render, UI and key-handling code is unchanged since v1.
- Build status: the earlier failing test is fixed and the build is green. That was never an accessibility finding.

## What passes
- **1.4.1 Use of colour:** every state has an icon and a text label. An ASCII fallback exists, and `NO_COLOR` is honoured.
- **2.1.1 Keyboard:** every action is reachable by keyboard, with no mouse dependence.
- **2.1.2 No keyboard trap:** `Esc` closes dialogs, and `q` and `Ctrl-c` quit.
- **2.4.3 Focus order:** dialog Tab order is logical, and the selection follows the session name.
- **3.3.4 Error prevention:** kill needs an explicit `y`, and Enter keeps the session.
- **3.3.3 Error suggestion:** errors state what to do next.
- **2.5.8 Target size:** there are no pointer targets.
- **2.3.1 Flashing:** the spec's 2 s row flash is not implemented, so there is no flashing risk.
- **4.1.3 Status messages, port change (new):** "Port 3000 is in use. Using port N instead." and "ait API listening on port N" are plain text lines. They are not conveyed by colour or position, so a screen reader or log reader gets them. The strict-mode error "Port N is already in use." is also plain text and says what happened.
- **3.3.3 Error suggestion, port change (new):** the README port section gives the next step (`PORT=8080`, `AIT_PORT_STRICT=1`) and the troubleshooting table lists the message.
- **Document structure of the README (new):**
  - It uses a numbered heading hierarchy.
  - Commands are in code blocks.
  - Tables have header rows.
  - There are no images and no colour-only meaning.
  - The page is easy to navigate with a screen reader (1.3.1, 2.4.6).

## Findings

| ID | Location | WCAG | Severity | Finding | Exact fix |
|---|---|---|---|---|---|
| A1 | `dashboard.js: refresh`, `render.js: lines` | 4.1.3 Status messages | Minor (was Major, partly fixed) | Waiting transitions now write `<names> now WAITING` into the status line for 6 s, directly above the hint line. That gives screen readers a stable text line, and the README says so. Gaps: the line is only a repaint (no announcement area is documented as such), it shows for 6 s only, and the bell remains the only audible cue. | Keep the fixed status line. Document in the README and `?` help that this line is the announcement area. Add `AIT_ALERT_TEXT=1` to keep the last waiting message until a key is pressed. |
| A2 | `render.js: dialogFor` ('help'), `ui.js: handleKey` | 2.1.1, 3.3.2 | Minor | Help closes on any key. Its text has no entry for `Esc`, `Tab` in forms, or `y` / `n` in dialogs. Unchanged since v1. | Add the lines `Esc closes dialogs`, `Tab next field` and `y confirms, n or Esc cancels`. Optionally close help only on `Esc`, `q` or `?`. |
| A3 | `render.js: boxLines`, `dashboard.js: draw` | 1.3.1, 2.4.3 | Major | Dialogs are drawn over the table rows, but the covered table text stays in the screen buffer. The real cursor is hidden (`\x1b[?25l`) for the whole session, so forms show no cursor. The `_` marker is the only focus cue. Unchanged. | While a form dialog is open, move the cursor to the active field (`\x1b[<row>;<col>H`) and show it (`\x1b[?25h`). Hide it when the dialog closes. Keep the `_` marker. |
| A4 | `render.js: styler.row` and the header `st.dim` | 1.4.3, 1.4.11 | Minor | `dim` (`\x1b[2m`) is used for IDLE, DONE and UNKNOWN rows and for the column header. Faint text can fall below 4.5:1 on common palettes, and amber (33) is weak on light themes. The label text carries the meaning, so no information is lost. Unchanged. | Do not dim state labels or the header. Use the default foreground for IDLE and DONE. Add `AIT_HIGH_CONTRAST=1` (bold, default colour). Document that colours follow the terminal palette. |
| A5 | `render.js: lines` | 1.4.10 Reflow | Minor | Below 60 columns or 15 rows the UI is replaced by "Terminal too small. Need at least 60×15." Zoomed or large-font users get nothing, although `ait ls` works. Unchanged. | Append `Use "ait ls" for a plain list.` to the message. Optionally degrade to a one-column list (`id state name`) down to 40 columns. |
| A6 | `render.js: lines` (selected row) | 2.4.7 Focus visible | Minor | Selection is shown by `▶` (ASCII `>`) plus reverse video. With braille or screen-reader use only the marker is present, and `>` is easy to miss. Unchanged. | Add `Selected: <name>` to the status or hint line, rendered only when no status message is showing. |
| A7 | `dashboard.js: refresh` and `draw` | 2.2.2 Pause, stop, hide | Minor | `draw()` runs after every 1 s refresh and every key. It repaints the full screen even when nothing changed, so readers or braille displays may re-announce it. Unchanged. | Keep the last drawn frame, and repaint only when it differs. Update "Since" every 10 s once past one minute. Add `AIT_REDUCE_MOTION=1` to stop ticking. |
| A8 | `render.js: dialogFor` | 3.3.1 Error identification | Minor | Dialog errors read `! message`. The field they belong to is only implied. Unchanged. | Prefix with the field, for example `! Name: Use letters, numbers, - and _ only.` |
| A9 | `render.js: dialogFor` ('help') | 3.3.2 Instructions | Minor | The help overlay says `<prefix> Tab` literally. The real prefix is only in the status bar and in `ait doctor`. | Pass `tmux.prefix()` to the model and print the real prefix in the help overlay. |
| A10 | `notify.js` | 1.4.1, 4.1.3 | Minor | The bell is always rung, with no switch. A deaf or hard-of-hearing user, or one who finds the bell disturbing, cannot turn it off. The text cue exists now (A1). | Add `AIT_BELL=0` to switch off the bell. Document it in the README configuration table. |
| A11 (new) | `README.md` | 3.3.2 Labels or instructions, 1.3.1 | Minor | The README is now complete, but it has no accessibility section. `NO_COLOR` and the ASCII fallback are mentioned only in passing. It does not say that: (a) `ait ls` is the plain-text alternative to the dashboard, (b) the status line is where waiting changes appear, or (c) no screen reader or 200% font test has been recorded. Section 13 (gate results) still says "record here". | Add a short "Accessibility" subsection to the README covering: `NO_COLOR=1`, the ASCII icons, the 60×15 minimum with `ait ls` as the alternative, the status-line announcement area, the bell switch once A10 is done, and a results line for the VoiceOver and 200% font checks. |
| A12 (new) | `README.md` section 7, `src/serve.js` | 3.3.2 Instructions | Minor (note) | Section 7 explains the port fallback clearly. It does not say that the new port appears only in the line printed at startup, which a user who reads output with a screen reader must find. It also gives no exit codes for strict mode. | State that the actual port is on the line `ait API listening on port N`. Give the exit codes: `npm start` exits 1, and `ait serve` exits 7, when `AIT_PORT_STRICT=1` and the port is busy. |

## Conditions for release
1. Fix A3 so that forms show a real cursor on the active field.
2. Fix A4 by not dimming state labels and the header.
3. Fix A1 by documenting the status line as the announcement area (a README line plus `?` help). `AIT_ALERT_TEXT=1` is optional.
4. Fix A2, A5, A6, A7, A8, A9, A10, A11 and A12, or record why each is deferred.
5. Test once with a screen reader (VoiceOver with Terminal), at a 200% font size and with `NO_COLOR=1`. Record the results in the README (section 13 and the new Accessibility subsection).

Verdict: PASS WITH CONDITIONS
